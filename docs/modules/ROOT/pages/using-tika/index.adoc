= Getting Started with Apache Tika

Four ways to use Tika. Pick by how you need to call it.

[cols="1,2,2"]
|===
|Integration |What it is |Best for

|xref:using-tika/java-api/index.adoc[Java API]
|Tika embedded in your Java application
|Tight integration and full control over parsing behavior

|xref:using-tika/cli/index.adoc[Command line (`tika-app`)]
|A standalone jar you run per file or per directory
|Quick extraction, shell scripts, one-off tasks

|xref:using-tika/server/index.adoc[Server (REST)]
|A standalone service with an HTTP API
|Language-agnostic integration and microservice architectures

|xref:using-tika/grpc/index.adoc[gRPC]
|A standalone service speaking gRPC
|High-performance, cross-language communication
|===

NOTE: tika-grpc is more exposed by default than tika-server: no transport security, no per-caller
authorization, and its core fetch-and-parse surface is always on. (Its most dangerous
capabilities — runtime fetcher/iterator changes and per-request parse configuration — are off by
default.) Run it only on a trusted, access-controlled network. See
xref:using-tika/grpc/index.adoc#_security[Security].

For large volumes of documents, xref:pipes/index.adoc[Tika Pipes] adds fault-tolerant, scalable
processing and works with all four.

To run the server or gRPC service from a published image rather than a distribution zip, see
xref:using-tika/docker.adoc[Running Tika in Docker].
