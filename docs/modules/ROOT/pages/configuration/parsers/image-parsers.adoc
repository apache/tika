= Image Parsers Configuration

Options shared by the parsers that read EXIF, IPTC and ICC metadata through metadata-extractor:
`jpeg-parser`, `tiff-parser`, `raw-tiff-parser`, `heif-parser`, `bpg-parser` and `web-p-parser`.
Each parser takes the options under its own name; `raw-tiff-parser` takes them alongside its
preview options.

[cols="1,1,3"]
|===
| Option | Default | Description

| `includeIccCurvesAndLuts`
| `false`
| Write ICC profile tags whose data is a tone curve or lookup table (`curv`, `para`, `mft1`,
  `mft2`, `mAB`, `mBA`; in practice `icc:Red TRC` and friends) to the metadata. Off, an
  sRGB-profiled JPEG loses about 30 KB of numbers per file that nothing queries, and the cost of
  formatting them. Header and text tags (`icc:Profile Description`, `icc:Color space`,
  `icc:Device manufacturer`, ...) are always written.
|===

[source,json]
----
{
  "parsers": [
    "default-parser",
    {
      "jpeg-parser": {
        "includeIccCurvesAndLuts": true
      }
    }
  ]
}
----

The same option can be set per request on the `ParseContext`, keyed by
`org.apache.tika.parser.image.ImageMetadataConfig`, which then applies to every one of these
parsers.
