== OCR of pages (`ocr`)

The PDF parser does not OCR anything itself. It renders pages and hands each rendered image to the
text recognizer resolved for the render type (`image/png` by default): the engine named in the
top-level `text-recognizers` list, or, with no list, the one found among the loaded parsers and
logged at startup. See xref:configuration/index.adoc#text-recognizers[Configuration]
for choosing the engine and xref:configuration/parsers/tesseract-ocr-parser.adoc[Tesseract OCR]
for its options. The `ocr` block controls only rendering and when OCR runs:

`strategy`::
`NO_OCR` never renders. `OCR_ONLY` emits the engine's output instead of extracted text.
`OCR_AND_TEXT_EXTRACTION` emits both. `AUTO`, the default, renders a page only when its extracted
text is poor by the `strategyAuto` thresholds; the page's extracted text is then *replaced* by the
engine's output when the engine is a text recognizer (Tesseract, Tess4J, a VLM with
`textRecognizer` true) that actually wrote text, and kept unchanged otherwise, including when no
engine is available, `maxPagesToOcr` is spent, or the engine times out. `AUTO` with no engine
behaves as `NO_OCR`.
`dpi`, `imageType`, `imageFormat`, `imageQuality`, `renderingStrategy`::
How pages are rendered before they reach the engine.
`maxPagesToOcr`, `maxImagePixels`::
Budgets per document and per rendered page.

Inline images embedded in a PDF are a separate path: with `extractInlineImages` on they are
parsed as embedded documents, so `image-parser` enriches each one with the same engine. A scanned
page that is one full-page image is therefore OCR'd twice when both are on.

Page renders emitted as embedded documents (`imageStrategy` set to `RENDER_PAGES_AT_PAGE_END` or
`RENDER_PAGES_BEFORE_PARSE`) are enriched by the PDF parser itself, once per page: the text
recognizer where `strategy` says so, and every other enricher (an image embedder, a tagging VLM)
on every page, with its results such as `tk:chunks` landing on the PDF. The embedded copy of a
render is parsed for its metadata but not enriched again, so no page reaches the same engine
twice, and `NO_OCR` means no page OCR anywhere while the other enrichers still see every page.

`pdf:ocr-page-count` records how many pages tripped the verdict, whether or not an engine ran.

== Tagged PDFs (`markedContent`)

A tagged PDF carries a structure tree: paragraphs, headings, lists, tables, links, and which
content is an artifact (running headers, footers, page numbers). The `markedContent` block says
whether the parser follows that tree. Every page's words and spacing still come from the same
text stripper and the same `sortByPosition`, `enableAutoSpace` and tolerance settings; the tree
only decides which XHTML elements the words land in and, across blocks, their order.

`strategy`::
`NONE`, the default, ignores the tree and writes what the stripper writes. `TAGS` follows the tree
on every page that has tagged text. `AUTO` follows it only on pages that pass the gate below and
writes the other pages exactly as `NONE` would. A PDF with no structure tree is written as with
`NONE` whatever the strategy, and `detectAngles` always wins.
`minCoverage`, `maxDanglingRatio`::
The `AUTO` gate, per page. A page uses its tags only when the tree claims at least `minCoverage`
of the page's text (artifact content counts, since a producer that marks the body as artifact
has not described the page) and at most `maxDanglingRatio` of the tree's leaves for the page
point at content the page never draws. Both start loose (0.5 and 0.2) until a corpus says
otherwise; `minCoverage` above 1 turns every page back to the stripper.

With tags, a structure element becomes the XHTML element of the same meaning (`P` to `<p>`, `H1`
to `<h1>`, `L` to `<ul>` or `<ol>` by its `ListNumbering`, `Table`/`TR`/`TH`/`TD` to a table,
`Link` to `<a href>` when its annotation has a URI) and any other type becomes a `<div>` or
`<span>` with the type as its class. Text the tree does not reference follows the tagged content
of its page in `<div class="untagged">`, and artifact content in `<div class="artifact">`, so
nothing is lost and a consumer can drop headers and footers. The metadata says what happened:
`pdf:marked-content-pages-tagged`, `pdf:marked-content-pages-fallback`, and
`pdf:marked-content-rejections` with the reason per page that fell back.

The old boolean `extractMarkedContent` still loads: `true` is `TAGS`, `false` is `NONE`.

== Pages for inference (`inference`)

`input`::
What the parser releases to the xref:configuration/inference.adoc#pages[inference bindings]:
`["TEXT"]` by default. Add `PAGES` to render every page for a `PAGES` binding; the render is
the `ocr` render, made once per page for OCR and inference alike, and nothing is rendered
unless a `PAGES` binding runs for the request. Per request under `pdf-parser` in
`parse-context`, like the `ocr` block.
Every `ocr` option can be overridden per request through `parse-context` under `pdf-parser`; the
xref:using-tika/server/index.adoc[server documentation] shows the `NO_OCR` override as a preset.
