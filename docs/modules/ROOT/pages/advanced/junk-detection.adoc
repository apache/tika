= Text Quality Scoring (Junk Detection)

The `tika-ml-junkdetect` module scores how much a string reads like real text, in any
language it was trained on, without being told the language.  Tika uses it in two places:

* **charset detection**: of several decodes of the same bytes, which one is the real text
  (see xref:advanced/charset-detection-design.adoc[Charset Detection Pipeline]);
* **tika-eval**: the `tika-eval:languageness` score of extracted text, plus the worst window
  and coverage.

== What it detects

* **Mojibake**: text decoded with the wrong charset (Russian windows-1251 read as
  windows-1252, UTF-8 read as windows-1252: `Ã©`, double encoding).
* **Broken PDF fonts**: text layers whose fonts map glyphs to the wrong characters
  (`ïðåäñòàâëÿ`, legacy Indic and Greek fonts), which PDF metadata reports as fully mapped.
* **Garbage**: replacement characters, injected control characters, random bytes read as text,
  shuffled words and characters.

It does _not_ say which language a text is in (see
xref:advanced/language-detection.adoc[Language Detection]).  Code, data, tables and menus are
real text but not prose; they score lower than prose, so treat a low score on them with care.

== How it works

One linear model over hashed codepoint n-grams (1–3 codepoints, 2^21 buckets, int8 weights),
with two heads:

* a **pairwise** head, trained on pairs of a correct and a wrong decode of the same bytes, that
  says which of two texts is the real one (`compare`);
* a **pointwise** head, trained on clean text against junk, that scores one text (`score`).

Text is normalized first: full-width ASCII and half-width kana are folded, soft hyphens are
dropped, then NFC; whitespace runs become one space and digits become `0`.  There are no
per-script tables and no calibration step: one model covers every trained script.  Training uses
Wikipedia sentences and web pages, train splits only; see
xref:advanced/junk-detection-build.adoc[Building the Junk Detector].

== Using the API

The public interface is `TextQualityDetector` in `tika-core`; `tika-ml-junkdetect` registers
`JunkDetector` through `ServiceLoader`.

[source,xml,subs=attributes+]
----
<dependency>
  <groupId>org.apache.tika</groupId>
  <artifactId>tika-ml-junkdetect</artifactId>
  <version>{tika-version}</version>
</dependency>
----

[source,java]
----
JunkDetector detector = JunkDetector.loadFromClasspath();   // once; immutable and thread-safe
TextQualityScore score = detector.score("The quick brown fox jumps over the lazy dog.");
score.getZScore();     // the pointwise logit: > 0 reads as clean text, < 0 as junk
score.getPClean();     // sigmoid of the logit
score.getCoverage();   // share of letters in trained scripts
----

=== Interpreting the score

* `getZScore()` is a logit, not a z-score; 0 is the natural boundary.  On clean web pages about
  1% score below 0.1; on clean Wikipedia sentences about 0.3% score below 0.
* `getCiLow()` and `getCiHigh()` equal the logit: there is no interval estimate.
* The score is **unknown** (`isUnknown()`) for empty text, text without letters (coverage NaN)
  and text whose letters are all in untrained scripts (coverage 0, `isUnmodeled()`).  An
  unknown score means "cannot judge", never "junk".
* `getDominantScript()` is the script with the most letters.

=== The worst window

A long clean document with one damaged island still scores clean as a whole.
`getModel().score(text)` also returns `getWindowMin()`, the lowest score over 200-codepoint
windows (step 100, at least 20 letters; NaN when there is no such window), and
`getWindowFracBelow0()`.  On clean web pages about 1% have a window below −1.1.

=== Comparing two decodes

[source,java]
----
String a = new String(raw, Charset.forName("windows-1252"));
String b = new String(raw, Charset.forName("windows-1251"));
TextQualityComparison result = detector.compare("windows-1252", a, "windows-1251", b);
result.winner();   // the label of the decode that reads as real text
result.delta();    // |pairwise logit|: the model's average opinion per differing n-gram
----

`delta()` averages over the n-grams the two decodes do not share, so it does not grow with the
amount of evidence: two decodes that differ in one character can still have a large delta.
`getModel().pairwiseDifference(a, b)` gives that amount.  The junk filter defers to a declared or
structural charset when the margin is below the model's `getDeferThreshold()` (chosen per model
by the trainer).

== tika-eval fields

[cols="1,3"]
|===
| Key | Value

| `tika-eval:languageness`
| The pointwise logit; −99 when unknown (no letters, or only untrained scripts).

| `tika-eval:languagenessMin`
| The worst window (the whole text if shorter than a window); −99 when unknown.

| `tika-eval:languagenessCoverage`
| Share of letters in trained scripts in [0, 1]; −1 when the text has no letters.
|===

== Limitations

* **Scripts**: only scripts with enough training text are covered (`getTrainedScripts()`);
  letters in others make the score unknown or, in mixed text, lower its coverage.
* **Short text**: a few words give a few n-grams; scores on very short strings are noisy.
* **Small damage**: a handful of replacement characters in a long page barely move the score;
  count them directly.
* **Not prose**: code, data, tables and menus score lower than prose without being junk.
