= Building the Junk Detector

The training pipeline, model format, and known limitations of the bundled
junk-detector model.  For usage, see
xref:advanced/junk-detection.adoc[Text Quality Scoring (Junk Detection)].

Corpus paths below are written as `<corpus>` and `<workdir>`; substitute your own.

== Model

A `HashedJunkModel` (`junkdetect.bin`): hashed codepoint 1–3-grams, 2^21 buckets, two int8
weight vectors over the same features.

* **Features.** `HashedJunkModel.normalize` (full-width ASCII and half-width kana folded, soft
  hyphens dropped, then NFC), every whitespace run to one space, every digit to `0`, a space
  at each end; then each codepoint n-gram (n = 1..3; a lone space is skipped) is hashed into a
  bucket.  The corpus builder, the trainer and the scorer call the same code.
* **Pairwise head.** Logistic regression with no bias on the L1-normalized difference of the
  n-gram counts of a correct and a wrong decode of the same bytes; antisymmetric by
  construction.  Used by the junk filter (`HashedArbitration`) and `compare()`.
* **Pointwise head.** Logistic regression with a bias on n-gram counts divided by the n-gram
  total: clean text against junk.  Used by `score()` and tika-eval; the worst-window score
  uses the same weights over 200-codepoint windows.
* **Deferral threshold.** Below this pairwise margin the junk filter trusts the structural,
  else the declared, charset.  Chosen per model by the trainer.
* **Trained scripts.** Scripts with enough letters in the training text; letters in other
  scripts are uncovered.

== Pipeline

Tools live in `tika-ml/tika-ml-junkdetect-tools`; the `train` profile builds a self-contained
jar.  Rebuild the bundled model with the driver script from the repository root:

[source,bash]
----
TIKA_JUNK_DATA=<dir holding the data> tika-ml/tika-ml-junkdetect-tools/train-junk-model.sh
----

The script names the data (its `CORPUS`, `GOLD`, `SAMPLE` and `SAMPLE_DOCS` lines are the
committed record of what trained the bundled model), builds the tools, runs
`BuildJunkTrainingData` and `TrainHashedJunkModel` into a fresh run directory
`<TIKA_JUNK_DATA>/<corpus>-runs/<time>-<commit>/` (log, built corpus, the exact uncommitted
diff if the tree was dirty, the deferral sweep, the cross-fit model) and writes
`junkdetect.bin` and `junkdetect.bin.provenance` to their classpath location.  Commit both
together; `ModelProvenanceTest` fails when they disagree.

[IMPORTANT]
====
Training choices are *not* CLI flags.  They are constants in `HashedTrainingConfig` (model) and
`JunkDetectorTrainingConfig` (corpus build); the provenance file records every one of them.
To change one, edit the file and commit it with the retrained model.
====

== Stage 1: corpus collection (`BuildJunkTrainingData`)

Collects clean UTF-8 sentences from language-specific source files, groups them by
Unicode script, allocates a byte budget per script, and writes 80/10/10
train/dev/test splits.

=== Data format

One directory per language (ISO 639 code), each containing up to two files:

`sentences_wikipedia.txt`::
  Line-numbered Wikipedia sentences: `\{lineNum}\{TAB}\{text}`, one per line.

`sentences_madlad.txt`::
  Line-numbered MADLAD-400 documents, same shape.  Documents use literal
  two-character `\n` escape sequences as sub-sentence separators; the tool splits
  on those first.

=== Script group detection

Each language directory's dominant script is found by sampling up to 2,000 lines
and histogramming `Character.UnicodeScript`, excluding the `COMMON`, `INHERITED`,
and `UNKNOWN` pseudo-scripts.  The plurality script wins, subject to a 1% floor
that suppresses spurious wins on mixed-script text.  Languages sharing a dominant
script are pooled into one training group.  No groups are hardcoded — the set is
derived from the data.

=== Entropy-proportional byte budget

Scripts are not comparable by sentence count: CJK text has thousands of distinct
3-byte UTF-8 codepoints and high byte-bigram entropy (~10.4 bits), while Arabic
clusters in a narrow 0xD8–0xDB high-byte range (~7.2 bits).  A sentence-count
budget would badly over-represent low-entropy scripts.

The tool instead splits the total byte budget in proportion to each group's
empirical byte-bigram Shannon entropy, estimated from a 200 KB sample per group:

[source]
----
H(script) = -Σ p(a,b) · log₂ p(a,b)   over all observed bigrams (a,b)

budget(script) = totalBudget × H(script) / Σ H(all scripts)
----

Within a group the budget is spread evenly across member languages, and a
per-language cap keeps one large source (`zho` has 8 GB of MADLAD) from dominating
a multi-language bucket.

=== Train/dev/test split

[cols="1,1,3"]
|===
| File | Split | Purpose

| `\{script}.train.gz`
| 80%
| Training units for `TrainHashedJunkModel`.

| `\{script}.dev.gz`
| 10%
| Not read by the trainer; the split for iterative evaluation.

| `\{script}.test.gz`
| 10%
| **Held out completely.**  Final reported numbers only — never a model or
  threshold decision.
|===

`manifest.tsv` records per-script entropy, budget, bytes written, sentence count,
and contributing languages.

=== Running it

[source,bash]
----
java -cp tika-ml-junkdetect-tools-*-tools.jar \
  org.apache.tika.ml.junkdetect.tools.BuildJunkTrainingData \
  --data-dir   <corpus>/madlad/data \
  --output-dir <workdir>/junkdetect
----

`--data-dir` and `--output-dir` are required; `--dry-run` (detect scripts and show
the budget without writing) is the only other accepted argument.  The source
corpus must carry a `manifest.tsv`; the tool refuses a directory without one, and
records the corpus name and the manifest's SHA-256 in `source.tsv` in the output
directory.

=== Config constants

`JunkDetectorTrainingConfig` holds everything else:

[cols="3,1,4"]
|===
| Constant | Value | Effect

| `TOTAL_BUDGET_BYTES`
| 500,000,000
| Total UTF-8 byte budget across all script groups.

| `PER_LANGUAGE_CAP_BYTES`
| 5,000,000
| Cap on one language's contribution to a multi-language bucket.  Single-language
  buckets ignore it.

| `MIN_TARGET_SCRIPT_FRAC`
| 0.05
| Minimum fraction of non-COMMON codepoints that must be in the bucket's target
  script.  Low enough to keep legitimate mixed-script content (kanji + kana,
  Korean with hanja), high enough to reject off-target lines.

| `MIN_BYTES_PER_SENTENCE`
| 50
| Minimum UTF-8 length for a sentence to pass the quality filter.

| `MAX_PUNC_FRAC`
| 0.30
| Maximum fraction of ASCII punctuation and digits.  Filters bullet lists and
  code snippets.

| `MIN_DEV_SENTENCES`
| 500
| A script below this in the dev split is excluded — too little data for reliable
  calibration, which inflates FPR.  At `DEV_FRAC = 0.10` that is ~5,000 sentences
  total.

| `SCRIPT_SAMPLE_LINES`
| 2,000
| Lines sampled per language for dominant-script detection.

| `ENTROPY_SAMPLE_BYTES`
| 200,000
| Bytes sampled per group for the entropy estimate.

| `SEED`
| 42
| Shuffle seed.

| `DROP_SCRIPTS`
| GOTHIC, THAANA
| Script buckets excluded: THAANA has 216 native train sentences, and 40% of the
  Wikipedia "gothic" directory is English text *about* Gothic.
  `MIN_TARGET_SCRIPT_FRAC` removes CANADIAN_ABORIGINAL, CHEROKEE and TIFINAGH implicitly.

|===

== Stage 2: training (`TrainHashedJunkModel`)

Train data only.  The gold file must hold `split = train` on every row; the trainer refuses
anything else.

*Inputs*

* the built Wikipedia corpus (stage 1), sampled per (script, language): sentences and ~2 KB
  documents, capped; each sentence's language is found through the corpus, with the builder's
  own line parsing and normalization (the run stops if more than 1% of units find none); a fixed
  share is also used in upper case, so all-caps headings read as clean;
* gold train web pages with charset labels, split into an even and an odd half; optional
  `damage_spans` mark damaged regions;
* a sample of web pages with unanimous charset votes (no gold pages), for real-decision pairs.

*Pairwise pairs*

* Wikipedia units against synthetic wrong decodes (encode in a plausible source charset, decode
  with the others);
* gold pages (even half) under a fixed list of decoders, and through the real detector chain:
  the label's decode of the probe against every other candidate the junk filter would weigh;
* the web sample, as is and re-encoded into every charset of its script that holds its letters,
  through the chain the same way.  One page in ten is held out to monitor the fit.

*Deferral threshold (cross-fit)*

A second pairwise model is fitted on the odd half and run over the even half as the junk filter
would.  On the pages where deferring to the anchor changes correctness, the threshold grows in
bands of 1.0 while each band fixes at least twice as many pages as it breaks.  The per-page
records and the cross-fit model are kept in the run directory.

*Pointwise examples*

Clean: Wikipedia units and clean gold pages (even half).  Junk: one synthetic version of each
(wrong decode, word or character shuffle, injected U+FFFD / control characters, random bytes),
and the damaged regions of gold pages whose spans were located by rule, padded by 100 code
points (the rest of those pages counts as clean).

*Quantization and checks*

Weights are quantized to int8 (the 99.99th percentile of |w| maps to 127).  The trainer fails
unless the written model scores its own features identically.

== Model binary format (JUNKHNG1)

Gzipped, big-endian: magic `JUNKHNG1`, version byte, log2 of the bucket count, max n; pairwise
scale (float), the pairwise int8 weights, deferral threshold (float); pointwise scale (float),
bias (float), the pointwise int8 weights; trained-script count (int) and
`Character.UnicodeScript` names.  The loader rejects anything else, including trailing bytes.

== Tests

* `HashedJunkModelTest`: golden buckets and scores under a seeded test model (any change to
  feature extraction fails it), the loader's rejections, round trips.
* `HashedTrainerTest` (tools): the trainer's features equal the runtime's, the language lookup
  finds every builder sentence, the threshold rule, damage spans, an end-to-end train on a
  synthetic corpus.
* Behaviour of the bundled model: `JunkDetectorSmokeTest`, `DecodeCorruptionDiscriminationTest`,
  `LatinSiblingComparisonTest`, `UnmodeledScriptTest`, `JunkFilterEncodingDetectorTest`.
